# Isolated checkout API

`POST /api/checkout` uses the draft ETHN database only. Legacy UI and routes do not call it; this is not a deployment or payment flow. Send JSON containing `ownerToken` (customer-minted random UUID v4 capability), `idempotencyKey`, `date`, `ranges` (`courtId`, UTC ISO `start` and `end`), `displayedTotal` and `displayedVersion`. Preserve the owner token and key for retries. Both first success and replay return 200. Never send rates or server time. Requests with an Origin must match the request URL origin. The existing per-process proxy limit is not a distributed abuse control; forwarded IP headers require a trusted proxy.

Configure `ETHN_DATABASE_URL` with the dedicated non-owner `ethn_checkout` login (or `ethn_checkout.<projectref>`); no legacy database variables are used. URI query parameters are rejected. Remote connections require `ETHN_DATABASE_CA_FILE` pointing to a trusted CA PEM file; TLS certificate and hostname verification remain enabled. Local plaintext requires both `ETHN_ALLOW_LOCAL_DATABASE=1` and a loopback hostname (`127.0.0.1` or `localhost`), and is disabled in production. Provision and audit the restricted role separately as described in `db/ethn/README.md`; a username check cannot prove role privileges.

Pool is lazy, limited to two connections per process, and has connection, idle, statement and query timeouts. Production serverless connection lifecycle and hosted TLS have not been measured or verified. Do not deploy until those, authorization, remaining workflows and legacy cutover are approved and tested.
