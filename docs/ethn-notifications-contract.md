# ETHN persistent inbox backend

Migration `db/ethn/0022_notifications.sql` follows 0018–0021 in fresh-schema order. Do not apply to existing/hosted data without separately approved migration review. It creates recipient-scoped persisted rows; inserts are unique by recipient and event key. Database role has only notification SELECT, INSERT columns, and `read_at` UPDATE column.

`reconcileInbox(pool, verify)` requires enabled current staff, then creates bounded (up to 100 each) pending-unverified-payment, due-within-30-minutes, overdue pending, and expired late-exception events for that staff account. The 30-minute urgency threshold is fixed in SQL; it is not configurable. Repeated reconciliation is idempotent. `listInbox` exposes current-recipient rows, newest 50; optional unread-only filter. `markInboxRead` accepts UUID, updates only recipient-owned row's `read_at`, and is idempotent. Callers must provide staff-authenticated routes and CSRF validation for writes.

Titles and bodies are fixed generic text. Event keys and internal links include booking/payment UUIDs only; no customer name/contact, amounts, proof, owner hash, or tracking capability is included. The cron backstop is `GET /api/cron/ethn-inbox`; it authorizes through `CRON_SECRET` and reconciles at most 100 enabled recipients. It exposes only recipient/created counts and no IDs. No scheduler is provisioned, so periodic execution is not guaranteed. Optional browser push is a separate opt-in module (`0028_web_push.sql`, `docs/ethn-push.md`); inbox continues working without configured keys, permission or device support. No scheduler or real-device delivery guarantee is implied.
