# Prepaid walk-in — implementation and corrected verification

2026-11-20. Local only. No hosted migration, browser verification or deployment.

## Implementation

Migration `0013_walk_in.sql` permits accepted cash/GCash payment inserts under the restricted server login. `createWalkIn` verifies staff, locks staff → settings → courts → candidate held bookings, expires stale overlapping holds, resolves the schedule using checkout's existing validator, then atomically inserts a confirmed booking/item/allocation, accepted payment and audit. GCash requires configured merchant instructions and a unique accepted reference. Cash does not require merchant configuration. No customer email or tracking capability is created.

API: `POST /api/ethn/admin/walk-ins`; UI: `/admin/walk-in`.
