# ETHN isolated local database regression runner

Runner: `test/run-ethn-local-db.mjs`. It is standalone; no npm script or dependency added. Requires Node 22.6+, installed `pg` dependency, and local PostgreSQL binaries (`initdb`, `pg_ctl`, `psql`). It never reads project `.env` files or uses a configured/remote database. Each selected test gets a new disposable DB initialized from all 28 numerically ordered `db/ethn/*.sql` migrations; runtime tests use `ethn_checkout`, administrative setup URLs use local postgres. Separate test databases prevent fixture collisions.

Windows example (adjust PostgreSQL version/path):

```powershell
$env:ETHN_TEST_PG_BIN = 'C:\laragon\bin\postgresql\postgresql\bin'
node test/run-ethn-local-db.mjs
```

Optional `ETHN_TEST_TEMP` selects scratch parent; default is OS temp `opencode` directory. The runner creates its own child directory, random cluster password and port, stops its own cluster, then removes its scratch data. Do not interrupt it if possible; if interrupted, remove only the uniquely named `ethn-db-*` child left in that scratch directory after confirming its PostgreSQL process has stopped. Never point PostgreSQL binaries or cleanup at an existing database cluster.

Selected tests: staff management, exception review, walk-in, booking read, calendar blocks, audit read, finance, outcomes, Open Plays, sales, extensions, notifications, venue, timing policy, expense corrections, integrated workflows, extension review and optional push (mocked sender, no provider calls). Tests lacking DB environment variables are excluded; this is not a claim that every conditional database test is covered. Some older conditional tests expect purpose-built profiles/fixtures, so no automatic synthetic fixture assumptions are made.
